# Feature Documnetation: Multi-Session Ad Score Down-weighting

## Overview
To improve ad diversity and combat Click-Through Rate (CTR) decay, this feature introduces a mechanism to **down-weight ad scores** if a customer has already seen the same ad across multiple unique sessions in the past 7 days.

Data analysis shows that CTR starts dropping significantly after a customer's **3rd impression** of the same ad. Until real-time capping is fully implemented, this batch workaround serves as a frequency-capping proxy to force fresher, alternative ads to the user.

## Technical Architecture & File Changes
### 1. Configuration (`next_uk.json`)
We introduced the Actions table to the read configuration layer to track historical impression and click data.
- **Added Key:** `"bq_actions": "marketingdata_prod.warehouse.bq_actions_next_uk"`
### 2. Helper Functions (`Assignment.py`):
A new helper function, `generate_repeat_ad_sessions(SESSIONS, ACTIONS)`, processes both web and app traffic over a rolling 7-day window (excluding current day).
*This is restricted to desktop SB/OC and app PLP data, until tagging elsewhere improves*
- **Web Filter:** `SiteCountry == "UK"`, `Device` in `Mobile/Desktop`, `PagePath` in `/shoppingbag` or `/secure/checkout/complete`.
- **App Filter:** `SiteCountry == "UK"`, `ScreenName == "PLP"`.
- **Core Action Metric:** Looks specificallly for `Action == "Banner Impression - Next Ads"`.

#### Down-weighting Matrix
The function counts distinct `UniquevisitID`s per `AccountNumber` and `AdSeen` (mapped from `Level2`), then applies the following multipiers to the `MultiSessionDownweightScore`:
| Sessions Seen (Last 7 Days) | Score Multiplier |
| :--- | :--- |
| <= 2 | `1.0` (No Change) |
| 3 | `0.84` |
| 4 | `0.80` |
| 5 | `0.70` |
| >= 6 | `0.50` |

### 3. Codebase (`map_theme_scores_to_ads.py`)
This script pulls the multipliers generated by `Assignment.py` and applies them directly to the main ad scoring pipeline (`df_score_components`).

#### The Levenshtein Fuzzy Match Workaround
> ⚠️ **Important Caveat for New Devs:**
> Currently, there is a naming inconsistency between Google Analytics (GA) tracking data and our internal control sheets. Because of this, the table join cannot be a strict equality match. 
> 
> Instead, we use a **Levenshtein string distance** match:
> * It computes the edit distance between `AdSeen` and `UniqueAdID`.
> * It ranks matches via a window function (`MatchRank`) sorted by shortest distance.
> * A **hard threshold of 10 (`max_distance_threshold = 10`)** is enforced. If the closest match has an edit distance > 10, the match is discarded and the multiplier defaults back to `1.0`.

Finally, the script recalculates the ad's final score:
$$\text{Score} = \text{Score} \times \text{MultiSessionDownweightScore}$$
